# 技術選択

## 潰しがきく技術

### Vite, Vue, Tailwind, Typescript

Webだけじゃなく、モバイルアプリでも、PCアプリでも使える。

そのため、これだけ覚えれば、ほとんどすべてのアプリケーションのUIが作れるようになる。

詳細は、`capacitor-test`、`electron-test`参照。

UIは、当分は、これだけで回していけると思う。

capacitorは、Burger King、Southwest Airlinesなどで利用されている。

electronは、VSCode、slackなどで利用されている。

ただし、モバイルアプリについては、スタンドアローンならいいけど、そうじゃない場合は、今後は、難しくなっていくパターンもあるかも。

詳細は、`rails-app`参照。

### Rails, Laravel

無難な選択肢。

### npm

必須。

### Node

ニッチな分野では、いろいろ使う。

ただし、日本では、恩恵が薄い。

潰しがきく技術だけど、おすすめしているわけではない。

詳細は、`spa-test`参照。

## 危うい技術

### SPA的なもの

SPA的なもの（SPA、Node SSR、Node SSG）は、コストがかかるのが、経営者にバレ始めているので、今後は難しくなりそう。

さらに、ハイブリッドMPAで、似たようなものを低コストで運用できるのも、バレ始めている。

そもそも、日本での、SPA的なもののシェアは、そこまで多くない。

なぜなら、現場では、実用的かどうかが大きなファクターになるから。

おまけに、日本では、エッジサーバーの費用対効果が悪い。

詳細は、`spa-test`参照。

### Docker

実務で使うのはしょうがないけど、学習用途で使うと、初学者の心を折る危険がある。

実務でも、しょっちゅう動かなくなったり、変更でビルドが必要になったりするので、できれば使いたくない技術。

特に、開発環境は、ホットリロードがあるので、Dockerだといろいろと厄介。

Dockerを使いたくない場合は、wslのような仮想環境を使い、セットアップの手順を、どこかにまとめて共有するというやり方もある。

esaか、ドキュメント共有用のgithubレポジトリでいいと思う。

### Django

実務では、扱いが難しくなりやすい。

AI関連の個人用途ならいいとは思う。

詳細は、`django-test`参照。

### React

扱いが難しい。

今は、昔の技術資産が残っている状態。

Laravel界隈とかでは、Vueには対応しているけど、Reactに対応していないものも出始めている。

詳細は、[評価](./evaluation.md)参照。

### Push通知、WebSocketサーバー

管理が面倒だったことが、バレ始めている。

### ddd、クリーンアーキテクチャ

下手すると、逆効果。

詳細は、`ddd-test`参照。

### コードレビュー

いろいろと難しい。

詳細は、`github-test`参照。

### テスト文化

扱いが難しい。

詳細は、[ユニットテスト](./test.md)参照。

### UI目的のモバイルアプリ

IEが廃止されたため、WEBアプリケーションとの違いがほとんどなくなってきている。

モバイルアプリには、マーケティングというメリットもあるので、現在は、そこだけが生命線。

詳細は、`rails-app`参照。


## しぶとい技術

### レガシーMPA

もともと、現場のシェアが大きい。

さらに、SPA的なものから、MPAへの揺り戻しがおきているため、レガシーMPAは、今後も、大きなシェアで残りそう。

ただし、レガシーMPAではなくて、ハイブリッドMPAに慣れていったほうがいいとは思う。

レガシーMPAだと、不便な部分があるのも事実。

レガシーMPAに、少しだけくっつければ、ハイブリッドMPAになる。

詳細は、`laravel-app`、`rails-app`参照。

### PHP

時代の要望に合わせて、柔軟に変化し続ける言語のため、Web業界のCOBOLには、なかなかならなかった。

むしろ、Web業界のCOBOLは、Reactだった。

ただし、Reactは、コンセプトは優秀だったと思う。

## 最後に落ち着くであろう技術

### ハイブリッドMPA

都合がいいから。

詳細は、`laravel-app`、`rails-app`参照。

反証として、`spa-test`参照。

おそらく、ここに落ち着くと思うので、最初から、ここを目指すのが、最短経路だと思う。

楽をしたい人は、目的地は、ここにしておいたほうが無難だと思う。
