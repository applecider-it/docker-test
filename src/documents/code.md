# 理想のコードと認知負荷

理想のコードは、１行もない状態のコード。

リファクタリングは、その状態に近づけるほうが、認知負荷が下がっていい。

コードは、何かを追加するよりも、何かを削るほうが、都合がいいことが多い。

## 段階的

リファクタリングじゃなくても、最初から、理想のコードに近づけられるほうが都合がいい。

ただ、それは意外と難しいので、ある程度形になってから、少しづつ削ればいい。

技術も同じで、技術を追加するよりも、削るほうが都合がよくなる場合がある。

これも、最初から判断するのは、意外と難しいので、ある程度分かった段階から、少しづつ削ればいい。

## 感覚的な判断

ここで重要になってくるのは、形式的ではなく、感覚的に判断すること。

なぜ、感覚的な判断が必要かというと、最適解は感覚的にしかわからないから。

そして、感覚的な判断は、適性がある人じゃないと身につかない。

適性が合わないことを強制される環境では、適性の不一致が起こる。

その場合は、リファクタリングや技術選択は、形式的な対応になり、かえって悪化することもあると思う。

## なぜ、形式的なものに、価値を感じてしまうことがあるのか

自分の適性にあわないことは、感覚的にわかることができない。

そうなると判断基準にできるのは、形式的なものになる。

つまり、自分の適性に合わないことを理解する手がかりは、形式的なものだけになる。

その結果、状況によっては、形式的なものに価値を感じるようになることがある。

つまり、形式的なものに囚われてだしたということは、自分の適性にあわないことを、無理してしている状態に陥っているということでもある。
